## 容量与图片回收

schema 4 新增 `clipboard_usage` / `clipboard_assets`。记录插入、删除、正文/类型/收藏修改通过同一事务内的触发器更新计数；非图片按存储内容的 UTF-8 字节计算，共享图片原图和缩略图只计一次，另保留每记录 256 字节的估算。统计仍是剪贴板逻辑容量，不能解释为 SQLite、便签、密码箱或整个目录的实际磁盘占用。

已有库迁移时仅首次读取已引用图片的文件元数据；后续采集、缩略图写回与导入分别更新资产尺寸。常规容量检查不再装入全库正文或逐个检查图片文件。明确调整限制时仍计算实际清理数量供用户确认，改为流式读取字节数、ID 和图片引用元数据；确认与删除共用写保留事务。

超限和 TTL 清理每批最多 100 条，批间释放 DB 锁；容量清理逐条查看事务内计数，达到目标即停，收藏、手动 Key、DPAPI Key 与带标签记录继续受保护。TTL 查询不返回普通文本正文。便签不参与这两类淘汰。

采集文件创建及引用提交与图片回收协调；回收取得写保留后再核对引用，避免检查结束后新引用刚好提交。只删除应用 `images/` 下的相对文件与对应缩略图，失败保留零引用台账，启动/每小时最多重试 100 个。缩略图解码留在锁外，写回前重新检查引用，防止晚到结果重建已回收文件。批间让出执行权不等于保存延迟已达标，实际锁时长和压力测量仍待完成。

备份图片仍在 DB 锁外准备。存在性冲突复核移入 `BEGIN IMMEDIATE` 后，与资产尺寸、记录、设置、密码箱、便签和来源去重共同提交或回滚；epoch 检查保留。

## 原生桌面发现与边界

使用独立标识 `com.copycreator.qa20261007`、独立 WebView profile 和 QA 数据目录，没有打开生产用户数据库。已在实际 520×600 WebView 完成中文便签新建、保存、换行与末尾空格保留、链接引用保存；浅色编辑截图保存在 `output/optimization/QA-notes-20261007/screenshots/note-editor-light.png`。这不替代 IME、最小窗、缩放、暗色/英文与文件选择验收。

第一次归档暴露 WebView 的 `Illegal invocation`：保存屏障通过对象属性调用浏览器计时器，导致非法 receiver，Node 的普通计时器未暴露此差异。已用包装函数保留正确调用方式，并补浏览器 host timer 回归测试。初次更新 QA EXE 时原进程尚未退出，复制失败，后续启动的仍是旧二进制，故不能把那次流程计为修复后复验。已准备检查进程路径、等待退出、严格检查复制错误并记录哈希的更新流程。

QA 重启的自动审批曾因账户额度而未完成，操作未执行；没有绕过审批。账户状态恢复后，更新并启动的 QA EXE 哈希为 `4405594e1e9ef00cb19162ea9821fa8011001e927e2c0400419358c21fdd2a3d`，使用 `frontend-accounting`。完整“新建/保存/链接/归档/取消归档/删除/回收站只读/恢复”原生流程通过，恢复后正文和引用一致，计时器修复已复验。

随后在已加载协调器的 transport 返回处注入一次“原生已经提交、确认丢失”，真实 native 命令和 SQLite 仍执行。确认失败后本机稿保留；继续输入并重试，前两次请求完全一致，之后最新修改另行保存，原记录 revision=2。再用独立原生命令制造并发修改，编辑器进入冲突并保留本机稿，点击另存副本成功；原记录保留另一写入者的正文和 revision=3。测试结束恢复 transport。Tauri 内部 invoke 属性不可写，最初针对该属性的注入未生效，不能算作故障验收；驱动已改为检查插桩确实可用后才运行。
