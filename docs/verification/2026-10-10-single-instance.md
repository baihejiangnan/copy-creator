# Windows 单实例与重复启动验证

2026-10-10，按用户“修改”授权修改开发源码。接手时 main 已有 AGENTS、TODO、发布/更新说明与历史记录的未提交修改，保留并增量合并。基础版本保持 0.2.28，未提交、推送、打包或发行，已公开二进制不包含此修复。

## 实现

- `single_instance.rs` 在旧更新/管理员父进程等待之后、Tauri Builder 之前运行。Windows `Local` 命名空间按登录会话分隔，用户 SID 与 identifier 的 SHA-256 摘要区分用户/应用；同 identifier 的不同版本、安装/便携路径共用锁。没有按数据库路径多开，也没有向轮盘 WebView 增加独立应用锁。
- 用非继承命名 mutex 句柄的存在确定唯一实例，不依赖托盘/通知窗口是否已经创建。首实例的锁尚在时，第二份程序直接结束；初始化失败或 IPC 被权限保护拒绝时不能继续打开数据库、启动监听或创建托盘。
- 自动复位事件在获取锁之前创建/打开，启动早期的手动唤起可被保留；多次信号合并。一个阻塞等待线程将操作提交主线程，至多一个待执行回调。回调保存外部目标、恢复最小化、调用现有 `show_main` 发出可见性事件并请求焦点，不调用 toggle。隐藏启动不发信号。没有传递文件路径、参数队列、用户内容或凭据。
- 对象 DACL 只允许当前 Windows 用户，保留系统默认完整性保护。低权限进程可能无法通知高权限首实例，此时本次启动结束，不绕过保护多开；跨权限实际唤起仍待验收。首轮显式完整性标签实验因权限/标签错误失败，最终源码不设置 SACL 或请求相关特权。
- 普通重启继续经过便签/设置保存、后台排空及敏感资料清理，在主线程执行已有 Tauri restart 前释放 mutex。更新/管理员重启沿用 `--copy-creator-update-parent`，在获取单实例锁之前等待旧 PID 退出。异常进程结束由内核关闭句柄，不留下永久锁文件。

## 实际检查

Windows x64，锁定现有依赖，仅增加 windows crate 的 `Win32_Security_Authorization` feature，Cargo.lock 未变。

| 检查 | 结果 |
| --- | --- |
| 手动重复启动，主实例尚未安装 listener | 真实第二测试进程退出，保留一个唤起信号，消费后无第二信号 |
| 隐藏重复启动 | 真实第二进程退出，主实例无唤起信号 |
| 12 个并发第二实例 | 子进程全部成功退出，原实例保持唯一，信号合并为一个 |
| identifier 隔离及正常关闭 | 不同 identifier 可独立获取锁；同 identifier 被拒绝；关闭原实例后可重新取得锁 |
| 普通重启最终释放 | 父进程仍存活时释放锁，后继可取得，其他重复实例仍被拒绝 |
| 异常终止 | 真实锁持有者子进程被强制终止，随后可重新取得锁；失败时也有夹具清理 |
| `cargo test --manifest-path src-tauri/Cargo.toml --locked` | 161 通过、0 失败、5 忽略；main 和 doc-tests 也通过 |
| `rustfmt --edition 2021 src-tauri/src/single_instance.rs` | 通过，仅格式化新增文件 |
| 文档本地链接、`git diff --check`、新增源码格式检查 | 307 个本地链接存在，diff 与 rustfmt check 通过 |
| `scripts/qa-process-isolation.ps1` | 启动前/收尾核对完整旧 QA 根目录，无存活 QA 应用；未停止其他进程 |

5 个忽略项为 4 个原有基准与 1 个仅供父测试启动的子进程夹具；后者已由本轮父测试实际执行，不是功能测试被跳过。测试只创建唯一合成 identifier 和临时文件，不创建完整 Tauri 应用，不读取实际数据库/密码箱/剪贴板或备份，也不注册系统快捷键或改写自动启动项。

首轮完整测试中旧文件测试遇到系统 Temp 拒绝访问，单实例安全标签实验也失败；最终移除标签操作，沿用仓库已记录的隔离临时目录方法。最终成功日志为 `output/optimization/single-instance-20261010/unit-all-r3.log`，临时目录为同路径的 `tmp/`；此前失败记录不记为通过。
