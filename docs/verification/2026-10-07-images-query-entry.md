## 实现

- 缩略图每个 WebView 最多 3 个在途、80 个排队；完整预览独立 1 个在途、8 个排队。相同 epoch/记录/路径请求合并，消费者离开时取消其订阅；最后消费者离开，尚未进入原生的任务移除。已接受原生任务不宣称可强制取消。
- 缩略图缓存最多 80 条/12 MiB 字符串预留；完整预览最多 4 条/24 MiB 字符串预留，按每字符两字节核算。不是全进程、解码像素或 WebView IPC 内存上限。
- 主列表 IntersectionObserver 同时处理进入和离开，窗口隐藏停止排队和悬停工作，缓存补入不再驱动拉取循环。轮盘隐藏时返回空渲染，未显示不查列表/不挂图片；显示后仅可见附近图片请求，避免每条缩略图订阅整个 store。
- 剪贴板查询一个在途/一个可替换待执行，同签名合并；目录/查询代次校验，事件使可见列表刷新、隐藏列表延后。按 `created_at,id` 游标稳定排序及追加去重；仅查询返回页的标签，保留旧命令 offset 兼容。
- 原有受保护 API Key 分类的两条 SQL 分支不一致，新测试发现后统一补回 DPAPI 条件。字面通配符、同时间排序、新插入不挤动后页、受保护 Key 标签及脱敏结果通过回归。
- 目录身份总线使剪贴板图片/列表、短语、密码箱、翻译结果及设置失效；旧异步读取不得覆盖新状态。便签继续使用已注册保存屏障及自身身份校验。
- `main.tsx` / `radial.tsx`、`index.html` / `radial.html` 独立入口；轮盘不导入 App、设置编辑与更新启动逻辑。主 App 保留更新启动和密码箱会话，短语/翻译/密码箱/设置/关于页面及样式按需加载，设置保存状态/限制对话框样式保留共享。

## 双窗口持续图片与隐藏动画发现

当前默认 `native-release-notes-scrollbars`（SHA `70F828C57A0B290ADCBA57F0DE6B9D89F62C091E2CBE1D8D0972F0B171966E41`）由[持续图片驱动](../../scripts/verify-images-continuous.cjs)在两独立 WebView 执行，传输观察不使用 Debugger 断点。[观察器](../../scripts/qa-native-fetch-observer.cjs)先用真实存储路径请求自检，锁定 Tauri 2.11.1 的实际通道为 WebView postMessage；仅记录命令/回调计数，不输出内容或调用密钥。

`images-continuous-1791506327230.json` 通过：60 初始 PNG 加十批各五项，两窗每批都包含完整 110 个 ID；每窗缩略图峰值 ≤3、完整预览 ≤1，实际缓存各 35 缩略图、约 12.36MB 预留，主窗一个完整预览约 6.29MB。限额分别是每窗 80/12MiB 缩略图、4/24MiB 完整图；全应用允许六个缩略图/两个完整图在途，不能写成全局三/一。主窗/轮盘可见阶段缩略图请求 101/148，列表请求 21/22；十次原生事件刷新后隐藏 10+30 秒，列表/图片计数保持，轮盘图片 DOM 为零。新增数据来自合成 SQLite 夹具后真实事件投递，不冒充系统图片连续捕获。

同字节 PNG 的冻结 R0 store 算法对照：20 个缩略图重复调用发 3 次原生请求，当前 1 次；10 个完整预览重复调用发 10 次，当前 1 次，返回 URL 字节一致。冻结旧 store 使用真实 Zustand vanilla 与当前后端读取适配器，不挂旧 UI/listener；因此只证明重复请求减少，不声称旧 EXE 的整体 CPU/内存/延迟收益。

计数通过没有掩盖后台问题。该轮[进程树采样汇总](../../scripts/summarize-images-memory.py)的隐藏稳定观察 29.946 秒仍为 **18.42% 单核 CPU**，private 中位数 **919.40MB**，原生进程约 12.41MB、该段 CPU 为零。清理恢复单列，不混入隐藏阶段。后继诊断 `images-continuous-1791506624830.json` 中，原生隐藏但 `document.hidden=false`，主窗仍有运行中的 `thumb-spinner`，轮盘已无动画。两页 V8 CPU profile 约 30 秒绝大部分 idle，JS GC 各约 26ms，不能把全段开销直接归为 JS 回收。

同进程可逆观察：原状态约 30 秒单核 **23.80%**；只暂停正在运行的 CSS 动画后约 30 秒 **0.94%**；恢复同批动画后约 30 秒 **18.62%**。这支持隐藏占位动画是 CPU 热点；顺序采样的 private 回落不能单独归因为动画暂停，也不宣称整体 80MB 达标。源码针对 `ImageThumb` 令占位动画仅在图片可见且原生窗口可见时运行，保留同一占位尺寸和视觉资源，默认构建复验另记。

失败轮保留：`1791506050223` 观察器只覆盖 fetch，通道自检失败，未计为图片通过；`1791506302064` 要求刚挂列表时没有任何在途任务，前置条件不成立，改为从实际 active 值开始峰值计数。另一次短成功轮 `1791506148529` 未隔开恢复界面且采样短，不用于稳定 CPU 结论。各轮均精确移除自己的 PNG/记录，停止 QA 后恢复并字节校验 4 格式剪贴板；最新诊断包装器 `controlled-clipboard-1791506620846.json` 通过。全根实时实例检查随后为零，未访问正式库或停止正式便携进程。
