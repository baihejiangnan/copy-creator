# 普通复制粘贴的存储身份与实际工作排空

## 真实发现与修正

在 `native-release-lifecycle-reload`（SHA `09f8425a0762b8a872cfeb45fbfad479eb5d8c5688aee92dd9250b3c9f6b3acb`）使用[复制竞态驱动](../../scripts/verify-copy-storage-race.cjs)，点击真实便签“复制正文”，在 WebView 传输入口暂留该请求，随后通过真实设置页和原生文件框迁移到空目标，最后放行旧请求。

`copy-storage-race-1791434680210.json` 为复现：epoch 1→2 后原生命令仍成功，系统剪贴板等于旧正文。只使用以 QA 前缀开头的合成内容；原剪贴板由外层助手仅在内存保存。包装器 `controlled-clipboard-1791434677532.json` 通过，停止 QA 后 4 格式恢复/字节校验。

普通 `copy/paste_text/image/file` 现在强制携带 `expectedStorageEpoch`；取得接受许可后、任何文件/剪贴板副作用前核验身份。六个命令把实际操作放入受登记的 blocking worker，许可一直保留到解码、复制、焦点恢复及最后一次按键释放完成；命令等待实际结果，忙和失败不再返回成功。错误不包含文件路径或正文，新增中英文复制/粘贴/忙提示。采集互斥、敏感剪贴板保护与原有图片格式保留。

便签复制、剪贴板/短语粘贴、API 地址操作、带注释复制及翻译结果复制统一走存储身份封装；异步全文读取前捕获身份，不能等读取完成后再绑定新身份。便签复制错误保留正确文案，已卸载或跨存储的旧操作错误不发布到新编辑界面。原生图片复制缓存按 epoch 失效，防止相同相对路径复用旧库图片。

托盘记录的 epoch 与行在同一连接锁内取得，菜单动作携带 epoch，再经过同一接受/身份/worker 规则；旧菜单不能把记录 ID 直接解释为新库记录。普通粘贴在修饰键超时或目标焦点未确认时失败，Ctrl 在错误路径也释放。

三个前端实际 store 回归先因缺少 native epoch 失败，修复后前端 **74/74**、类型/定向 lint/生产构建通过。原生增加同路径缓存失效及托盘动作身份解析回归，全量 **131 通过 /3 忽略**。误用仓库未安装的 tsx 的首个检查未执行测试，不算通过；随后按项目 `pnpm test:unit` 得到真实失败与修复结果。
