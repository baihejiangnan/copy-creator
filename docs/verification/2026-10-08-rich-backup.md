## 备份分项计时实现与未完成的桌面尝试

原生 `db_metrics` 增加备份 worker 排队/执行耗时，以及 export_snapshot、preview_snapshot、image_conflicts、vault_config、commit、committed_epoch 六个连接范围的等锁、持锁、SQL 数量和 SQLite profile 毫秒数。只有 diagnostics 编译安装 profiler/输出这些日志；日志只有固定阶段名、成功布尔和数字，不记录 SQL、参数、路径、token、Key、密码或正文。默认错误码、事务、排他 lease 与两个后台槽保持。

worker 计时从后台槽接受后至实际 worker 启动，并另报 worker 执行；不包含用户选文件或前端保存屏障等待。持锁范围包含其中 Rust 工作，SQL profile 约毫秒精度；不能拿 profile=0 当作 SQL 免费，也不能将各连接范围的总和当作全部原生锁或文件系统时间。导入图片解码/准备和备份密码 KDF 仍在 DB 锁外。代码存在不等于实际时长验收通过。

## v3 富内容与真实回滚

[富内容驱动](../../scripts/verify-backup-rich.cjs)经实际设置 UI 和精确所属 Windows 文件对话框操作。reports/backup-rich-1791390155267.json 全部通过：

- 原始便签正文 75,497,472 字节（72MiB），本轮补 268 条；12 张收藏 PNG 共 603,762 字节；预览共 2,375 便签/85 引用、7 个合成 API Key、6 条合成网站资料（本轮新建 2 条）。
- 导出 v3 文件 **102,709,462 字节**，认证载荷 **77,031,929 字节**，为 74MiB 上限 **99.2748%**，仍小于 100MiB 文件限制；实际 UI/对话框/导出合计 5,007ms，不是纯加密耗时。
- 导出后修改本机便签/设置，删除本轮两条账户和十二张图片，迫使恢复真正写入图片与账户。实际认证预览 2,819ms，报告 1 个冲突副本、2,374 条重复跳过。
- 在目标便签插入阶段注入 SQLite trigger 故障，真实导入失败 1,381ms。设置、剪贴板/标签、密码箱配置/记录、便签/引用/来源、容量/资产和稳定搜索映射的全部字段哈希，与导入前逐表相等；图片文件集合也相等，暂存图片被移除。epoch 不变，integrity=ok；不是只测内存数据库的模拟回滚。
- 去除故障后实际 UI 原地重试 990ms 成功，epoch 提升。12 张恢复图片 SHA 与原图片集合一致；两个账户全部字段（密码、自定义字段、恢复码等）一致，恢复后密码箱锁定、读取拒绝，正确合成主密码解锁。原便签本机改动保留，副本保留导出时 CRLF/空白原文。
- 重复导入跳过既有账户/来源，没有重复副本。近上限密文翻转一个字节后拒绝预览，没有确认导入按钮；数据库表哈希/图片集合保持不变。

reports/backup-legacy-1791390288476.json 三种格式实际选择/预览/导入均通过：保留现有便签原文及密码箱密文哈希；完整收藏原文/空白恢复；手动标记 Key 入库后受 DPAPI 保护且普通便签捕获拒绝。v0/v1 明文文件携带的翻译密钥字段被忽略，当前受保护值哈希保持；v2 可移植设置密钥导入后重新 DPAPI 保护。epoch 分别提升至 2/3/4。对应 controlled-clipboard-1791390285617.json 的 4 格式恢复/字节校验通过。
