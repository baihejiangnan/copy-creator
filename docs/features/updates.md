# 关于与检查更新

侧边栏底部的「关于」按钮打开项目弹窗，显示项目名称、当前安装版本、作者、MIT 许可证、仓库和上游项目链接。

「关于」弹窗和「设置 → 更新」都提供「检查更新」按钮，共享检查进度、检查结果与上次成功检查时间。发现新版本时，可查看更新说明，点击「下载并验证」下载当前运行方式对应的签名包，再由用户选择安装或打开新版；始终保留 GitHub 发布页入口。缺元数据、缺包或缺签名时显示具体原因，可到发布页手动下载。

设置顶部按「常规、剪贴板、翻译、数据、更新」分类。常规包含语言、开机启动和快捷键；剪贴板包含保留时间、去重、容量、清理和图片处理；数据包含存储目录和备份。分类栏保持可见，内容独立滚动，切换分类保留备份表单。

开机启动状态以系统插件为准。正式标识保留既有 Copy Creator 启动项名称；其他应用标识使用包含 identifier 的独立名称，避免 QA 启动修复或设置开关改写正式项。已发生的旧 QA 同名副作用、恢复范围和真实开关验收见[自动启动隔离](../verification/2026-10-08-autostart-isolation.md)；未以开关通过代替登录启动验收。

设置无需点击「保存」：开关和选项立即保存，压缩质量滑块在松开后保存，文本及数字输入在失去焦点或按 Enter 后校验并保存。切换分类、离开设置也会提交有效输入；保存失败时保留修改并提供「重试」，离开设置后仍显示失败提示。读取设置失败时会暂时禁用输入，避免默认值覆盖已有设置。

翻译 API Key 输入框不会显示已保存的密钥，留空保留原值；输入替换值后自动保存，成功后清空输入框。删除密钥需点击「清除已保存的 Key」。快捷键先注册并保存成功，再移除原注册；冲突或保存失败会保留原快捷键。

降低容量上限若会删除历史，会先显示待清理数量；确认后设置和记录删除在同一数据库事务中完成。确认时数量变化会要求再次确认，取消保留原上限。收藏和受保护的 API Key 不参与容量清理。备份导入前需处理保存错误和待确认的清理，导入期间暂停自动保存，完成后重新读取设置。

清理历史、导入/导出备份、选择存储目录与重启仍通过各自按钮执行。

「自动检查更新」默认开启，每次会话启动至多发起一次自动检查，自动尝试至少间隔 24 小时；关闭后仅在点击按钮时检查。手动检查不受间隔限制，并等待同一正在进行的任务。开关立即保存到 SQLite，包含在备份中，导入备份或切换目录后界面同步恢复。自动检查发现新版时，侧边栏的「关于」图标显示蓝色提示点。

更新源是固定公开入口 [latest.json](https://github.com/baihejiangnan/copy-creator/releases/latest/download/latest.json)，不请求匿名 GitHub REST API，不需要客户端 Token。发布方只把签名元数据附在公开正式 Latest Release。0.2.26 已公开并附有该资产，匿名独立下载、验签、摘要与 Latest 指向已核对通过；更早的 0.2.25 不含此资产，其客户端访问时会提示「当前发布尚未提供更新元数据」，不能把 404 说成已是最新版。后续发布准备见 [发布规则 §9](release-rules.md#9-签名更新发行准备2026-10-09-接入)。

版本取自运行中的 Tauri 应用信息，与元数据的 `version` 做 SemVer 优先级比较；构建元数据不参与高低比较。`version` 使用应用基础版本，例如 `0.2.26`；可选 `tag` 保存对应个人版标签 `v0.2.26-baihejiangnan.1`，未提供时用 `v<version>`。发布页和下载地址绑定该标签；个人版标签不得指向不同基础版本。保留 `v` 前缀的版本输入兼容。

提交、推送、版本递增、构建与发布执行方式见 [推送与 Release 发布规则](release-rules.md)。沿用个人版标签时，每次新二进制须提高应用基础版本；仅把 `baihejiangnan.1` 改成 `.2` 无法让同基础版本的已安装应用发现升级。

检查超时 15 秒，元数据上限 1 MiB，兼容 UTF-8 BOM；下载超时 180 秒，程序上限 512 MiB，检查/下载最多 5 次重定向并保留 HTTPS/TLS 校验。两者共用 HTTP 客户端配置：有翻译代理时使用该代理，否则使用 reqwest 的系统/环境代理检测。错误显示固定中英文原因及可用的 HTTP 状态码，不输出代理凭据、原生错误中的用户路径或用户内容。错误经过 `finally` 和关闭/重开面板仍保留，只有下一次检查/操作替换。

自动间隔记录的是**尝试时间**，失败也计入；记录位于当前应用 identifier 的配置目录 `update-check-attempt.json`，不放入业务 SQLite 或备份。界面「上次检查」仍指本会话最后成功检查时间，跳过自动检查不会写成功结果。时钟回拨允许重新检查。进度/下载与两个入口共用，原生还有全应用 admission 门闸。

## 签名下载与升级

元数据采用 `version`、`notes`、`pub_date`、可选 `tag` 与 `platforms`，平台条目包含 `url`、独立 `signature` 和实际 `size`。便携键为 `windows-x86_64-portable`，文件名 `Copy-Creator-<version>-portable.exe`；安装键为 `windows-x86_64`，文件名 `Copy-Creator_<version>_x64.msi`。初始下载 URL 必须逐字匹配固定仓库、标签和对应文件名。允许 GitHub 正常 HTTPS 资产重定向。公钥编译进原生层；每个程序各自使用 Tauri/minisign 的签名，不能用 MSI 签名替代 EXE 签名。

下载前重新读取元数据，复核用户先前看到的版本、模式、URL、签名和大小；变化时要求重新检查。下载逐块限制实际字节数，声明大小存在时检查完全一致。临时文件与目标同目录，64 KiB 缓冲流式验签，验签通过后原子保留，传输/验签失败或交接取消会清理临时文件；不覆盖已有目标，已有文件仅在重新验签成功时复用。升级使用前再次验签，Windows 验证至进程创建期间拒绝文件写入/删除共享。

- **便携版**：新 EXE 存在当前程序目录，保留原 EXE。点击「保存并退出，打开新版」才启动新进程；新版在初始化存储、剪贴板和全局快捷键前等待旧进程退出，最多 30 秒，失败则结束新版。数据仍按既有应用路径规则存储，不能把便携理解为数据一定在 EXE 旁。
- **MSI 安装版**：新 MSI 存在应用 cache 的 updates 目录，点击「保存并退出，安装新版」才打开完整安装界面。MSI 的 registry component 记录本次安装 EXE 的绝对路径，并随卸载移除；只有当前 EXE 路径匹配才识别为安装版，复制出的 EXE 按便携处理。
- **旧 NSIS 与其他平台**：应用内 MSI 升级未承诺兼容，显示原因并保留发布页入口。此前没有此标记的旧 MSI 也须先手动升级到带标记的版本；安装/卸载/升级实际验收见下文。

升级复用原生生命周期请求、前端统一保存屏障与后台排空。保存失败、超时、窗口会话替换或本地文件再次验签失败时不启动新版、不退出当前程序。退出、备份和目录操作会取消正在进行的更新网络任务并等待实际下载/验签 worker 完成。成功创建新进程后才按现有原生退出路径清理并结束当前进程。检查或下载本身不会安装/执行文件。

实现接入不等于公开更新链路与安装升级验收完成。0.2.26 的六文件发行集、标签绑定、草稿转公开与匿名独立下载验签已完成，但真实客户端发现/自身版本比较、旧 0.2.25 手动过渡与 MSI 安装升级仍属未执行边界；相关本地测试、构建及剩余范围见 [签名更新验证](../verification/2026-10-09-signed-updates.md) 与 [0.2.26 发行记录](../verification/2026-10-09-release-026.md)。旧 0.2.25 客户端仍走原 API，不会自动取得本次实现，须手动升级一次。

2026-10-10 按用户要求发布 0.2.27 为正式 Latest，用于从 0.2.26 内测试检查、签名下载与升级；相较 0.2.26 仅提高版本号，业务逻辑与完整 MSI 安装界面保持一致。用户真实升级结果尚待反馈，不据此收回桌面/安装验收缺口，见[0.2.27 测试发行记录](../verification/2026-10-10-release-027.md)。

支持简体中文、英文及亮色、暗色主题。弹窗支持 Escape、关闭按钮和点击遮罩关闭，关闭后恢复到入口按钮的键盘焦点。
